The JSON represents each quadratic number with rational and square-root coefficients and states the least-significant-bit coordinate convention. `PROOF.md:340-342`, `README.md:50`, and claim C4 consistently describe a feasible witness with the candidate universal error bound. They explicitly exclude a generally optimal projection or an RBM training algorithm. This avoids interpreting the output as an achieved minimum or a fitted finite-parameter RBM.

The worked example is usable. These values agree with `PROOF.md:346` and `examples/channel-witness.json`. The returned parameters remain in the closed product-mixture model. Users should retain the manuscript's closed-model convention when interpreting deterministic component coordinates.

The conditioning argument in `PROOF.md:355-380` specifies all the load-bearing application conditions: at most k components, closed Bernoulli parameters, conditioning on n-m coordinates, omission of zero-mass contexts, and multiplication of each local component weight by its context probability. The disjoint contexts retain the target context marginal, giving the displayed weighted KL identity. Substitution of m=3 and k=2 gives the budget 2^(n-2); monotonicity in the allowed number of components gives the stated larger-k corollary. The code implements that same construction by conditioning on the high bits and appending deterministic context coordinates (`witness.py:187-203`). Neither the proof nor claim C5 equates these larger mixtures with general multi-hidden-unit RBMs. The all-dimensional result is correctly attributed to the analytic construction, while four-/five-bit tests are described as finite implementation diagnostics.

The quantitative comparison is also appropriately narrow: the candidate three-bit bound improves the elementary one-bit error bound at the same exponentially growing component budget. - **Minor A1 — Explicit scaling guidance would improve reuse.** Locations: `README.md:52`, `PROOF.md:382`, and `witness.py:24-40,187-203`. The documentation states the exponential component count but does not explain the additional cost of the present implementation. It accepts a full table of 2^n probabilities and reconstructs every output probability by looping over every component and coordinate. With C returned components, that reconstruction alone uses O(n * 2^n * C) arithmetic operations; at the worst-case budget this is O(n * 4^n), before accounting for exact-arithmetic operand sizes. A reader should not interpret the all-n theorem as a scalable large-n routine. Suggested remedy: add one sentence beside the n-bit command/API description stating that the implementation is intended for small explicit probability tables, with exponential input/component requirements and a full reconstruction step; mention that reusing one `Oracle` amortizes certificate verification across queries. This is a nonblocking clarification: the current package makes no scalability or practical-performance claim, and no theorem or model boundary needs revision.
